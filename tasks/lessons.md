> Marble(主 worktree)有自己的 `tasks/lessons.md`,**兩份不共用** —— 本分支的教訓寫在本檔。

## 2026-08-07 — 收工報告一律走 `task_report_formatter`,不要退回自由格式

**What happened**: L-2 拍板與 commit 完成後,我用自由格式的分節散文回報(標題 + 表格 + 條列),
沒有套 `task_report_formatter` 的五段式範本。使用者指出這一點。諷刺的是,**同一個 session
稍早我才剛回答過「這個專案有沒有固定格式規則」**,並且自己列出了那五段 —— 我知道規則、
也知道它適用於「任務做完後的說明」,卻在真正做完時沒有套用。

**Rule**: 只要是**回報一件已完成的任務**(不論大小、不論使用者有沒有主動要報告),輸出必須是
`task_report_formatter` 的五段:一、執行總覽 / 二、完成項目與當前狀態 / 三、例外情況、發現與
數據修正 / 四、⚠️ 待決策與裁示事項 / 五、未完成與下一步工作。
判準是「**這一輪有沒有產出或改動**」,不是「使用者有沒有要求報告」。
若該輪只是回答問題、沒有動到任何東西,才用自由格式。

**Corollary**: 「待決策事項要獨立成第四段」這條特別容易漏 —— 自由格式下決策點會被寫成結尾的
順帶一提,失去應有的可見度。我這次就把「兩個未追蹤檔要不要 commit」與「P4a 要在來源補註解」
埋在最後一段散文裡。

**Corollary**: 已知規則 ≠ 會套用規則。剛複述過的規則最容易在下一輪被自己忽略,因為複述時
它是「知識」,執行時它必須是「檢查點」。收工前先問一次:這一輪有產出嗎?有 → 套範本。

## 2026-08-07 — 每一個 Bash 呼叫都要自己 `cd`,不能假設上一個呼叫的 cwd 還在

**What happened**: 寫上面那條教訓時,我直接跑 `cat >> tasks/lessons.md`,沒有先 `cd` 到 iceblue。
Bash 工具的 cwd **每次呼叫都會重置回主要工作目錄**(`zkThemeTemplate`,Marble 的 worktree),
所以那段文字被附加到了**主 worktree 的 `tasks/lessons.md`** —— 一個明確規定不得修改的檔案。
`git add` 失敗(Marble 的 `.gitignore` 第 35 行整個忽略 `tasks`)才讓我發現位置不對;
若不是它失敗,這個錯誤會靜默通過。已用 Edit 移除該段,`wc -l` 從 107 還原為 88、
`git status --porcelain` 與 session 起始快照逐行相同。

**Rule**: 在這個雙 worktree 的環境裡,**每一個會寫檔的 Bash 呼叫都要在同一行先 `cd` 到目標
worktree**,或改用絕對路徑。相對路徑的寫入(`cat >>`、`sed -i`、`tee`、`>`)是最危險的一類 ——
Read/Edit 工具強制絕對路徑所以不會出這個錯,Bash 不會。

**Corollary**: 「指令失敗」有時是唯一的護欄。`git add` 因為 gitignore 而失敗,是這次唯一
察覺異常的訊號 —— 一個**成功**的 `cat >>` 不會留下任何線索。動到檔案之後,
用 `pwd` 或 `git rev-parse --show-toplevel` 確認自己剛才在哪裡,比事後靠 diff 追查便宜得多。
