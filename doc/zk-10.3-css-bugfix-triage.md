# ZK 10.2.1 → 10.3.0.1 — Stock-CSS Bug-Fix Triage (Phase 3)

**Scope:** ZK fixed CSS bugs in its own stock (IceBlue) theme between the two versions. Marble's
CSS has diverged greatly from stock, so each stock delta is triaged — **not blindly ported** — as
`not-applicable` / `already-handled` / `port`.

**Method:** `git diff v10.2.1..v10.3.0.1` on the `zk/zul` `.less` sources (16 files), classified by
intent, then cross-referenced against Marble's compiled component CSS.

**Verdict: exactly 1 port.** `.z-window-noborder.z-window-noheader` content padding. Everything
else is not-applicable to a pure-CSS Material theme. The port is **applied and compiled**.

---

## Why most of the LESS delta is invisible to Marble

Marble is **pure CSS with custom properties — no LESS pipeline**. Three whole categories of the
stock diff therefore cannot apply:

1. **LESS→`calc()` arithmetic migration** (the bulk of the diff): e.g.
   `line-height: @baseButtonHeight + 6` → `calc(@baseButtonHeight + 6px)`,
   `border-radius: @checkboxSwitchHeight / 2` → `calc(...)`. These compile to **identical CSS
   values**. Marble already writes final values / `var()`s, so there is nothing to change. Affected
   files: `inp/combo`, `menu`, `tab/tabbox`, `wgt/checkbox`, `wgt/progressmeter`, `wgt/toolbar`,
   `wnd/panel`, `wnd/window`, `norm`, `_zkvariables`, `profiles/_compact`, `profiles/_default`.
2. **IE opacity-filter removal** (`_zkmixins.less`): dropped `filter:alpha(opacity=…)`. Marble is
   modern-browsers-only and never emitted it. N/A.
3. **New CSS-variable pipeline** (`_zkcssvariables.less` + `colors/_iceblue_css.less`, new blank;
   `_header.less` / `norm.less` import rewiring): ZK 10.3.0 is *introducing* CSS custom properties —
   the architecture Marble already ships. N/A.

Also N/A: pure whitespace / trailing-space cleanups (`panel.less`, `tabbox.less`,
`progressmeter.less`, `menu.less`).

## The applied port (#3)

Added to `src/main/resources/web/js/zul/wnd/css/window.css` (after the noborder/noheader block):

```css
.z-window-noborder.z-window-noheader .z-window-content {
    padding: 0;
}
```

**Divergence from stock (intentional):** stock also emits `.z-window-noborder.z-window-noheader
{ padding: 0 }` on the window root. Marble's `.z-window` root carries **no** padding (padding lives
only on `.z-window-content:146` and `.z-window-header:51`), so the root rule would be dead CSS and
is omitted per the surgical-changes principle. The content rule is the only effective part and
matches stock intent: a chrome-less window renders content flush, leaving inner spacing to the
developer.

Confirmed in compiled output:
`target/classes/web/marble/js/zul/wnd/css/window.css.dsp` →
`.z-window-noborder.z-window-noheader .z-window-content{padding:0}`.

## Conclusion

Of 16 changed stock LESS files, only one carried a fix relevant to a pure-CSS Material theme, and
it is applied. `npm run check:css-dsp` reports 0 missing after rebuild. Remaining validation is the
Phase 4 visual/computed-style spot check.
